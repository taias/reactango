# Skill: Testing (@testing)

Reactangoプロジェクトにおける自動テストの作成・実行に関するガイドラインと手順です。

## バックエンドのテスト (pytest / Django Test)
DDDの原則に従い、ビジネスロジックのテストを最優先します。

### 1. Domain層のテスト (最優先)
- フレームワーク（Django等）をロードせずに、純粋なPythonクラスとしてテストを実行できるようにします。
- エンティティの振る舞いや値オブジェクトのバリデーションをモックなしでテストします。

### 2. Application層のテスト
- ユースケースのテストです。
- 外部依存（データベースや外部API）のリポジトリは、インターフェースを実装した**モック（MockRepository）**に差し替えてテストを行います。

### 3. Infrastructure/Presentation層のテスト
- `pytest-django` などを利用し、実際にテスト用DBを構築してリポジトリのCRUD操作や、APIのE2E（エンドツーエンド）リクエストのテストを行います。

## フロントエンドのテスト (Jest / React Testing Library)
- カスタムフック（`useFetch` など）のロジックテストを重視します。
- 共通コンポーネント（`src/_fw/components/`）のレンダリングおよびイベント（クリック等）が正しく発火するかのテストを記述します。

## テストの自動実行
このスキルを呼び出すと、指定された領域（例: `backend/_project/domain/`）のテストコードを自動生成し、テストランナーを実行して結果を解析します。失敗した場合は原因を特定し、コードの修正案を提示します。
